Opening the Project
You can open either:

ResyPro.xcodeproj

Or the workspace (ResyPro.xcworkspace) if dependencies or package management require it.

Building and Testing
From Xcode
Select the “ResyPro” scheme and run/build as usual.

From CLI
To validate changes compile cleanly (preferred before committing):

/Applications/Xcode-16.3.0.app/Contents/Developer/usr/bin/xcodebuild \
  -scheme ResyPro \
  -destination "platform=iOS Simulator,name=iPhone 15" \
  build

✅ Note: There are no unit tests in the project yet. Don’t try to add or run tests at this stage.

If/when tests are introduced in local packages, you can run them individually using:

swift test

Coding Guidelines
Follow standard Swift style conventions.

Avoid committing .DS_Store or any autogenerated build files.

Document all public types in Swift packages.

Favor writing code in packages over the main app target.

Pull Request Tips
Provide a concise summary of your changes and how you validated them.

Ensure everything builds successfully using the CLI command above.

Keep commit history clean — squash before merging when possible.

# Contributor Guide

This repository contains the **ResyPro** iOS application along with several local Swift packages in `ResyPro/Packages/`. The project is licensed under the MIT license.

## Development Requirements

- Xcode 16.3 or later with the Swift 6 toolchain.
- Open `ResyPro.xcodeproj` (or a workspace that includes it) to work in Xcode.
- All new features should preferably live in local Swift packages under `ResyPro/Packages`.

## Building

Validate your changes by building from the command line:

```bash
/Applications/Xcode-16.3.0.app/Contents/Developer/usr/bin/xcodebuild \
  -scheme ResyPro \
  -destination "platform=iOS Simulator,name=iPhone 15" build
```

There are currently **no unit tests**. Focus on compiling successfully.

## Conventions

- Keep generated files such as `.DS_Store` out of version control.
- Follow standard Swift style. No formatter or linter is enforced yet.
- Provide a clear summary of changes and manual testing steps in pull request descriptions.
